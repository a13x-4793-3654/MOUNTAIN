# MOUNTAIN アプリ（最初の1機能：契約の一覧・詳細）

設計書（ワークブック v42）の DDL をもとに作った、実際に動くアプリの土台です。
「契約一覧」→「契約詳細（基本情報・紐付：会社／名義／口座）」までを、実データベースで動く形で用意しています。

## 構成

```
app/
├─ docker-compose.yml     … db + api + web を一括起動
├─ .env.sample            … 環境変数のサンプル（コピーして .env に）
├─ db/
│  ├─ schema.sql          … 49テーブルの PostgreSQL スキーマ（設計 DDL 由来）
│  └─ seed.sql            … 動作確認用のデモデータ（本番データではありません）
├─ backend/               … FastAPI（Python）REST API
│  └─ app/
│     ├─ main.py          … /api/health ＋ ルーター登録
│     └─ routers/
│        ├─ contracts.py  … GET /api/contracts, GET /api/contracts/{id}
│        └─ meta.py       … GET /api/masters/{category}（区分・状態の選択肢）
└─ frontend/              … React + TypeScript + Fluent UI（Azure/D365 風）
   └─ src/
      ├─ components/Layout.tsx     … 上部バー＋左ナビ
      ├─ pages/ContractsList.tsx   … 契約一覧（検索・絞り込み）
      └─ pages/ContractDetail.tsx  … 契約詳細（タブ：基本情報／紐付…）
```

## 技術スタック

- フロント：React 18 + TypeScript + Vite + Fluent UI v9（Microsoft デザイン）
- API：Python FastAPI + SQLAlchemy（psycopg3）
- DB：PostgreSQL 16（pgcrypto / pg_trgm）

## 起動方法（Docker がある環境。例：mountain-df）

```bash
cp .env.sample .env          # 必要に応じてパスワード等を変更
docker compose up -d --build
```

- 初回起動時、`db/schema.sql`（テーブル作成）→ `db/seed.sql`（デモデータ）が自動で流し込まれます。
- 画面：`http://<ホスト>:8080/`
- API：`http://<ホスト>:8080/api/contracts`（web コンテナの nginx が /api を api コンテナへ中継）

会社電話の既存拡張項目に合わせ、初期化スキーマには `phone_type`（50文字）と
`note`（255文字・任意）を含めています。これらが未適用の既存データベースを更新する場合は、
アプリの更新前に次の DDL を適用してください。適用済みの環境では追加作業は不要です。

```sql
ALTER TABLE company_phones ALTER COLUMN phone_type TYPE VARCHAR(50);
ALTER TABLE company_phones ADD COLUMN IF NOT EXISTS note VARCHAR(255);
```

## 主な API

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/api/health` | 稼働確認（DB 接続可否も返す） |
| GET | `/api/contracts?q=&status=&category=` | 契約一覧（検索・絞り込み）。既定は終了日が近い順 |
| GET | `/api/contracts/{id}` | 契約詳細（会社・名義・口座の紐付、外部管理番号、フラグ） |
| GET | `/api/masters/{category}` | 選択肢マスタ（例：`contract_status` / `contract_category`） |

## 開発（ローカル・Docker なしでも可）

- フロント：`cd frontend && npm install && npm run dev`（`http://localhost:5173`、`/api` は 8000 へプロキシ）
- API：`cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload`
  - DB は別途 PostgreSQL が必要。`DATABASE_URL` 環境変数で接続先を指定。

## 請求残額とダッシュボード

ホームの「期日超過の請求」と「対応が必要なこと」は、請求・入金画面と同じく、
契約ごとの入金合計（返金はマイナス）を古い請求から充当した**未入金の残額**で判定します。
充当順は発生日、作成日時、請求 ID の昇順です。取消済みの請求には充当しません。

- 支払期限を過ぎ、残額が正の請求だけを対象にします。入金済み・取消済みは含みません。
- 一部入金の場合、期日超過の合計金額と対応項目の表示金額は請求総額ではなく残額です。
- 対応項目には期日の古い請求を最大 5 件表示しますが、集計値は対象の全件を含みます。
- 入金の登録・編集・削除後は、次回の画面読み込み時に再計算します。保存済みの請求状態や残額を書き換える必要はありません。

## 契約審査の類似契約

審査一覧の類似件数、審査詳細、承認ダイアログは共通の条件で重複候補を判定します。
**同じ会社と同じ名義の両方が紐づく契約**、または**外部管理番号が一致する契約**だけが対象です。
名義のみ・会社のみの一致では表示しません。同一項目が複数一致しても、2 項目の一致とは扱いません。
複数の会社・名義が紐づく場合はすべての紐付けを照合し、審査対象の契約自身は除外します。

外部管理番号は単独の一致でも対象とし、大文字・小文字と前後の半角スペースを区別しません。
空の番号は一致と扱いません。類似件数は全件を集計し、候補一覧は従来どおり新しい順に最大 20 件表示します。

## 契約の紐付け先を検索・選択

契約詳細／編集の「紐付（会社・名義・口座）」タブで、会社・名義・口座／カードの
「紐付け」ボタンを押すと、既存レコードを検索できる一覧表が開きます。

- **会社**：会社名・カナ・市区町村で検索。会社名、カナ、所在地、電話を表示。
- **名義**：氏名・カナ・市区町村で検索。氏名、カナ、生年月日、所在地を表示。
- **口座・カード**：銀行名・支店名・名義カナで検索。区分・種別／カードブランド、銀行、支店、
  名義カナ、マスク済み番号、有効状態を表示。実番号やセキュリティコードの開示 API は呼びません。

キーワードを入力して「検索」または Enter で検索します。空欄なら全件が対象です。
既存の一覧 API（`/api/companies`、`/api/persons`、`/api/accounts`）へ `q`、`limit=20`、
`offset` を渡し、件数と「前の20件／次の20件」でページを移動できます。
最初のページだけの絞り込みではありません。「条件をクリア」で全件の先頭に戻ります。

表のラジオボタンで1件を選び、選択内容を確認してから「この契約での立場／紐づけ種別」を
選んで「紐付ける」を押してください。口座・カードは「既定にする」（初期値 OFF）も設定できます。
立場などの少数の選択肢は従来どおりドロップダウンです。検索・ページ変更時は誤登録防止のため
レコード選択だけを解除し、立場と既定の設定は維持します。

検索失敗時はエラーと再試行を表示し、保存失敗時は選択内容を保ったまま再保存できます。
保存中は二重送信・閉じる操作を防止します。Tab／矢印／Space で選択でき、狭い画面では表を横スクロールできます。
既存の紐付けの立場変更・既定変更・解除は従来の操作のままです。

## 契約者の表示

契約一覧・CSV・審査画面の「契約者」は、紐付け区分が「契約者」（`contractor`）の
名義（個人）だけを対象にします。請負者（`contractor2`）や保証人などの名義で代用しません。
契約者が未設定なら画面は「—」、CSV は空欄です。複数の契約者がいる場合は、
その中で最初に紐付けた名義を表示します。契約一覧の契約者名検索も同じ対象です。

文書差し込みで契約から個人を自動選択するときも同じ条件を使います。
画面で個人を明示選択した場合は、その選択を引き続き優先します。
審査の類似契約判定は表示用の代表者に限定せず、従来どおり全ての紐付けを照合します。

## 回帰テスト

バックエンドの依存関係をインストールし、PostgreSQL のテスト用データベースを用意して実行します。
テストは専用接続内の一時テーブルだけを使用し、各ケース終了時にロールバックします。
`TEST_DATABASE_URL` 未設定時はスキップします。
`test_record_lists.py` は同名レコードの安定したページ順、先頭ページ以外の検索、
口座一覧に暗号化済み実番号・セキュリティコードを含めないことを確認します。
初期化スキーマによる会社電話の作成と、既存の種別・メモの文字数上限も確認します。
`test_contract_parties.py` は契約者の区分・登録順・未設定時の表示、検索・CSV、
審査の代表表示と類似判定の独立性、差し込みの自動選択・明示選択を確認します。

```powershell
cd backend
$env:TEST_DATABASE_URL = "postgresql+psycopg://localhost/mountain_test"
python -m unittest discover -s tests -v
```

紐付けの UI 回帰テストは Playwright で実行します。テストが起動するローカル Vite サーバーと
架空の API 応答だけを使い、実 API・本番レコードには接続しません。
3種類の検索・ページ移動・選択・保存、カード／口座の既定値、エラーと再試行、遅延応答、
二重送信防止、同名レコードの識別、キーボード操作、狭い画面、既存の変更・解除を確認します。

```powershell
cd frontend
npm ci
npx playwright install chromium
npm run test:links
npm run build
```

インストール済みの Microsoft Edge を利用する場合、ブラウザーのダウンロードは不要です。
`$env:PLAYWRIGHT_CHANNEL = "msedge"` を設定して `npm run test:links` を実行してください。
テストのローカルポートは 4179 固定です（既存サーバーの再利用はしません）。

## メモ

- `person_phones` テーブルは Q54（名義の電話番号は保持しない）方針によりコメントで無効化しています（有効テーブルは 49）。
- 口座番号・カード番号は本スライスでは「マスク済み表示」のみを扱います（暗号化した実値の開示は今後のフェーズ）。
- 本番のリバースプロキシ（mountain-proxy）配下に載せる場合は、外側 nginx から web コンテナへ proxy_pass する構成に切り替えます。
